# SwiGLU vs SiLU: what the paper's gated feed-forwards cost, and what they buy

One variable, isolated: `Dense`'s activation in the 14 transformer feed-forwards (6 encoder
layers, 4 decoder layers x {q_dense, kv_dense}). This line defaults to a **gated SwiGLU**,
`main` defaults to a plain **SiLU**, and neither the encoder block nor `decoder_layer_config`
sets `dense_kwargs`, so every one of them takes that default. Gating doubles the inner
projection, so the two differ by 14 x 8,320 = **116,480 parameters**.

Two questions, one experiment:

1. **Timing.** The paper-tag reference run took 8 h 59 at 311 ms/step on a B200; the head-based
   v7 model at the same geometry and matcher took 7 h 26-7 h 40 at 251-255 ms/step. The
   parameter counts (819,683 vs 702,395) say the gated MLPs explain the whole gap. The
   pre-flights measure it directly.
2. **Physics.** SwiGLU -> SiLU is one of the three named suspects for head's jet-E IQR rising
   with energy where the paper's falls (`main`'s `studies/glow_jet_iqr`, whose bisect never
   ran). The full run is the first clean single-variable test of that suspect, with everything
   else held at the paper's code. **Its physics is expected to move; it is not a reproduction
   run.**

## The arm

`configs/clic_paper_small_silu.yaml`, generated by `make_config.py` from `configs/base_small.yaml`.
Every line that differs carries an `S:` comment; the diff is the run name plus two two-line
insertions. Verified: **703,203 trainable parameters**, i.e. exactly 819,683 - 116,480.

A `--config` overlay cannot express this. `decoder_layer_config` is a plain dict, so a second
config file *replaces* it wholesale rather than merging, silently dropping `dim`, `hybrid_norm`
and `num_heads: 8` -- the exact confound this arm must not have. Hence a full generated config,
the same pattern `studies/model_size/` uses.

Naming an activation in a config also needed `Dense` to resolve activation names
(`dense-activation-by-name`, merged 2026-09-13): `dense_kwargs` is an untyped dict, so
jsonargparse passes the string through unresolved and it used to fail inside `nn.Sequential`.

Both pre-flights run at the same commit on the same day, and the comparison that matters is

the reference's pre-flight read 367 ms/step where the full run did 311, which is the bias
`project_runtime.py` warns about.

The full run's 12 h comes from the SwiGLU reference's measured 8 h 59 x 1.3 (the submit script's
default). There is no SiLU measurement yet, and SiLU can only be faster, so the limit is
conservative by construction. Replace it with 1.3x this run's own wall time afterwards.

### Question 1 (timing): the answer is no

**The activation does not explain the step time.** Both pre-flights ran at commit 52b1843 on a
B200, both compiled encoder and decoder identically, and `ModelSummary` confirms the arm applied
(819,683 → 703,203). Cutting **14% of the parameters bought nothing**: the smaller model was if
anything marginally *slower*. That is the falsification condition this study wrote down in
advance, so the SwiGLU explanation for the 311 vs 251 ms/step paper-vs-head gap is dead, and
`README_HPG.md` no longer states it.

Read the step time from the tail, not the 300-step average: the average includes a one-time
compile, which is why the progress bar's cumulative figure (1.44 vs 1.34 it/s) is both higher
and in the other direction. Between steps 200 and 300 the two are within 6%.

Pre-flight numbers run high in absolute terms — the reference's pre-flight read 367 ms/step where
its full run did 311 — but that bias applies to both arms equally, which is the point of running
the control on the same day at the same commit. 41992199 will give a steady-state figure for the
SiLU arm to compare against the reference's measured 311.

**Leading explanation, untested:** at dim 64 the step is probably bound by kernel launches and
memory traffic rather than feed-forward arithmetic, so trimming MLP width does not show up. If so,
the paper-vs-head gap lives somewhere else — the norm/decoder rewrite and the incidence-head width
are the remaining post-paper changes, and neither has been isolated.

Question 2, the physics, is unaffected: 41992199 is still the first clean single-variable test of
the SwiGLU suspect from `main`'s `glow_jet_iqr` bisect, and it is now the *only* reason to run it.
